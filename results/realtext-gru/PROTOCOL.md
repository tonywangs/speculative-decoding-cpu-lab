# Real-text GRU comparison protocol

Specified before running the two recorded seeds (2026-10-19). The prior saved
experiments contain prompt lookup and n-gram drafts only, on synthetic inputs.
This comparison adds a one-layer GRU and real byte sequences. It makes no novelty
claim. It asks whether a small recurrent draft reduces end-to-end greedy decoding
latency relative to a cached transformer on these particular continuation tasks.

## Inputs and splits

The exact public downloads are retained in `corpus/`, with URLs, byte sizes and
SHA-256 in `corpus/sources.json`. No credentials or private inputs are needed.

- Dialogue: Shakespeare text from [char-rnn's tinyshakespeare fixture](https://github.com/karpathy/char-rnn/tree/6f9487a6fe5b420b7ca9afb0d7c078e37c1d1b4e/data/tinyshakespeare).
  Shakespeare's original text is public domain; the fixture is retained unmodified.
- Prose: Lewis Carroll's [Alice's Adventures in Wonderland, Project Gutenberg #11](https://www.gutenberg.org/ebooks/11).
  The original download and Gutenberg license remain intact. Only the bytes between
  its START/END marker lines enter the experiment. This is a US-public-domain work;
  see the retained source notice for other jurisdictions and redistribution terms.
- Python: [CPython v3.12.0 `Lib/ast.py`](https://github.com/python/cpython/blob/v3.12.0/Lib/ast.py),
  distributed with its original header and `corpus/python-license.txt` (PSF license).

Within each source, the first 80% of usable bytes are training, the next 10%
validation, and the last 10% test. These are contiguous source regions, not
independent documents. No window crosses a boundary. Candidate windows are 160
bytes long and nonoverlapping; each split's offsets are shuffled with seed
20261019 + 100×task-index + split-index. Task order is dialogue/prose/python;
split order is train/validation/eval. Select up to 512 training windows per task,
and exactly 12 validation and 12 test windows per task. Fewer training windows
are allowed when a source is short; batches sample all selected windows uniformly,
so task frequencies differ. Save every window's raw byte offset and tokens.

Exclude windows whose 96-byte prompt has fewer than 12 distinct bytes. Exclude
already selected exact prompts, and exclude held-out prompts occurring verbatim
anywhere in that source's training region. This prevents literal prompt reuse;
related syntax, phrases and author style can still cross splits. No corpus-level
out-of-domain claim follows. The evaluation windows are chosen without model
outputs. Validation is reported after training; it does not select checkpoints,
steps, architectures or draft lengths. Test continuations never train any draft.

Tokenization is lossless bytes: byte b maps to b+5; BOS is 0 and EOS remains the
legacy decoder's 4. IDs 1–3 are unused. Each training window is BOS + 160 bytes,
without a fabricated EOS at the arbitrary window boundary. Prompts are BOS + 96
bytes, followed by at most 64 generated bytes; early special-token output is
retained and counted honestly. This is continuation on three text genres, not
summarization, instruction following or semantic code completion.

## Frozen model and measurement design

Two paired target/draft seeds: 17 and 29. Target: two-layer causal transformer,
width 96, four heads, feed-forward width 384, context 161, vocabulary 261.
GRU: byte embedding 32, hidden width 32, one layer, linear output to vocabulary
261. Both train on the same selected training windows for 1,200 AdamW updates,
batch size 32, learning rate 0.003, weight decay 0.01, betas (0.9,0.999), eps 1e-8,
gradient norm clip 1, no dropout/scheduler, uniform batches with replacement.
Target initialization seed is S, batch seed S+2; draft initialization S+1000,
batch seed S+1002. The objective is next-byte cross entropy, without target
output distillation. Fixed step counts are not equal compute budgets.

Compare seven methods: cached greedy, prompt lookup k=2/4, training-only n-gram
k=2/4, GRU k=2/4. Lookup and n-gram use maximum order 4. The recurrent proposer
caches only committed history, processes newly committed tokens at each call,
and uses temporary hidden states for proposals. It recomputes accepted draft
tokens on the following call. Every decode resets recurrent state, so warmup,
method order and previous requests cannot confer a cached-prefix advantage.

One intra-op and one inter-op CPU thread, FP32, deterministic PyTorch algorithms,
identical target weights/cache/kernels per seed. Run seeds sequentially with no
other training or timing experiment from this project in parallel. Other workers
and shared-host interference remain outside this experiment’s control. Record hardware, affinity, environment, source and checkpoint
hashes. Historical synthetic timings are not matched baselines: rerun greedy,
lookup and n-gram contemporaneously on every new input.

Before timing, audit each method's cached target logits against full-prefix
logits and compare outputs with uncached greedy on all 36 test inputs. Warm every
case/method twice. Time seven repetitions, random base method permutation per
case with cyclic rotation, shuffled case order (seed S+3). Every method occupies
every position once per case. The timer includes state reset, both model prefills,
proposal construction, target verification, rollback and Python instrumentation.
Training, n-gram fit, audit, artifact I/O and warmups are outside the timer.
Every warmup and timed output must match the uncached reference or abort.
Save every paired measurement; no outlier or slowdown filtering.

Primary statistic: per-task median across cases of the median across repeats of
paired greedy/method latency ratios. Conditional 95% percentile intervals:
2,000 whole-case resamples (seed 314159), sorted draw indices 49/1949. Report
all methods for each seed, not just the fastest. Repeated timings do not increase
the number of independent targets or sources. Also retain median raw latency,
acceptance, calls, draft overhead, training time, target and GRU held-out quality,
and actual generated continuations. These are exploratory descriptive comparisons;
intervals do not establish population-wide significance or control multiplicity.

## Existing work and scope

[Leviathan, Kalman and Matias (ICML 2023)](https://proceedings.mlr.press/v202/leviathan23a.html)
provides the speculative decoding basis. This experiment uses deterministic greedy
verification, not their stochastic sampling acceptance rule.
[Prompt lookup](https://github.com/apoorvumang/prompt-lookup-decoding) is an existing
history-copy technique. The draft uses [PyTorch's GRU](https://docs.pytorch.org/docs/stable/generated/torch.nn.GRU.html);
using a recurrent small model is an implementation comparison, not a new method.

Completion requires saved source/splits/checkpoints/seeds, exact agreement for
every measured input, complete balanced paired timings, per-task honest speedup
or slowdown conclusions, training cost, runnable reproduction and an offline
verifier. A small integration test is only a software check; it is not a recorded
experimental result. Low target quality and GRU slowdowns remain results. Findings
are limited to these tiny byte models and texts, not capable pretrained LLMs,
large-model acceleration, sampling, GPU inference or production serving.

## Numerical audit amendment (2026-10-19)

The initial seed-29 audit exceeded the legacy logit closeness threshold on one
nonwinning logit. Before collecting its timings, `scripts/audit_realtext_numerics.py`
replayed all 252 case/method combinations for each saved target with exact
argmax and output checks intact. [Raw diagnostics](numerics.json) retain checkpoint
hashes and worst-error locations. Across 16,048,890 logit comparisons, one exceeded
`atol=1e-5` after `rtol=1e-4`; the maximum required absolute tolerance was
1.066889e-5. None exceeded 2e-5, and every argmax and generated output matched.
The approximate diagnostic now uses `atol=2e-5, rtol=1e-4`. Exact argmax and
output equality remain mandatory; this is not a tolerance on tokens. The unit
suite also checks that a numerically close change in the winning token fails.

Seed 17's completed timings remain unchanged. Seed 29 is rerun from the documented
seed because its interrupted attempt had not persisted training-cost records.
New checkpoints include those records to preserve them before audits. The raw
numerical diagnostic identifies the original checkpoints; a repeat run can have
different checkpoint bytes despite identical learned tensors. The completed rerun
was checked with `torch.equal` for every target and GRU state tensor: all were
exactly equal to the interrupted checkpoints used in the diagnostic. No parameter,
input, precision, inference kernel or timing design was selected using speedups.
